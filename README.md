# StepFlow

Платформа пошаговых инструкций для кейса TASKILLS. Интерфейс работает на Next.js, API — на Go. Профили, сессии, инструкции и прохождения хранятся в SQLite.

## Запуск фронта и бэкенда

### Локально на Windows

Установите Node.js 24+ и Go 1.26+. Выполните команды в корне репозитория в PowerShell.

```powershell
npm.cmd ci
npm.cmd run dev -- --port 3050
```

Откройте [localhost:3050](http://localhost:3050). Команда запускает Next.js и Go API вместе. Фронт принимает запросы браузера и передаёт их Go на порт 8080. Порт Go можно изменить через `BACKEND_PORT`. Если Go уже запущен отдельно, задайте `STEPFLOW_BACKEND_URL` с его адресом перед запуском фронта.

Для запуска собранной версии остановите dev-сервер, затем выполните команды в корне проекта.

```powershell
npm.cmd run build
npm.cmd run start -- --port 3050
```

Локальная SQLite-база создаётся в `.stepflow/stepflow.sqlite`. Другой путь можно задать через `STEPFLOW_DB_PATH`. Перед копированием базы остановите сервер и скопируйте каталог базы целиком.

### В Docker Compose

Запустите Docker Desktop и выполните команды в корне проекта.

```powershell
docker compose up -d --build --wait
docker compose ps
```

Откройте [localhost:3000](http://localhost:3000). Compose поднимает Next.js в сервисе `stepflow` и Go в сервисе `backend`. Порт Go 8080 доступен фронту внутри сети Compose. База хранится в томе `workspace-data`. При обновлении используйте прежнее имя проекта Compose, чтобы подключить существующий том. Для остановки выполните `docker compose down`.

## Локальный ИИ через Ollama

### Ollama и StepFlow на одном компьютере

1. Установите [Ollama для Windows](https://docs.ollama.com/windows) и запустите приложение. Сервер работает в фоне на `127.0.0.1:11434`.
2. Скачайте [Qwen 2.5 3B](https://ollama.com/library/qwen2.5:3b) (около 1,9 ГБ) и проверьте, что модель появилась в списке.

   ```powershell
   ollama pull qwen2.5:3b
   ollama list
   ```

3. Создайте `frontend/.env.local` или добавьте эти строки в существующий файл.

   ```dotenv
   AI_BASE_URL=http://127.0.0.1:11434/v1
   AI_MODEL=qwen2.5:3b
   AI_API_KEY=ollama
   ```

4. Запустите или перезапустите StepFlow через `npm.cmd run dev -- --port 3050`. Go добавляет `/chat/completions` к базовому URL. Значение `ollama` заполняет обязательную переменную приложения. Локальная Ollama [игнорирует этот ключ](https://docs.ollama.com/api/openai-compatibility#local-server-usage).

### Ollama внутри Docker Compose

В репозитории есть `compose.ollama.yml`. Ollama использует [сетевое пространство Go-контейнера](https://docs.docker.com/reference/compose-file/services/#network_mode), поэтому её API доступен Go по loopback. Модели сохраняются в томе `ollama-models`. По умолчанию используется [Qwen3-VL 2B Instruct](https://ollama.com/library/qwen3-vl:2b-instruct) с поддержкой текста и изображений. Чтобы выбрать другую модель, перед запуском задайте `OLLAMA_MODEL` и скачайте этот же тег.

Поднимите контейнеры и скачайте модель внутрь Ollama.

```powershell
docker compose -f docker-compose.yml -f compose.ollama.yml up -d --build --wait
docker compose -f docker-compose.yml -f compose.ollama.yml exec ollama ollama pull qwen3-vl:2b-instruct
docker compose -f docker-compose.yml -f compose.ollama.yml exec ollama ollama run qwen3-vl:2b-instruct "Reply in one word: OK."
```

Откройте [localhost:3000](http://localhost:3000). При работе с этим вариантом указывайте оба Compose-файла и прежнее имя проекта, чтобы сохранить доступ к вашей базе. Для NVIDIA добавьте `-f compose.ollama.gpu.yml` после `-f compose.ollama.yml`. Нужен [доступ к GPU в Docker](https://docs.ollama.com/docker).

На отдельном компьютере можно использовать OpenAI-совместимый API по HTTPS. Передайте `AI_BASE_URL`, `AI_MODEL` и `AI_API_KEY` через `frontend/.env.local` при локальном запуске или через корневой `.env` в Compose. Go принимает HTTP для `localhost`, `127.0.0.1` и `::1`. Для сетевого адреса, в том числе `host.docker.internal`, требуется HTTPS.

## Проверка ИИ

1. Если Ollama запущена на Windows, проверьте Chat Completions напрямую. Команда должна вывести ответ модели.

   ```powershell
   $body = @{
     model = 'qwen2.5:3b'
     messages = @(@{ role = 'user'; content = 'Reply in one word: OK.' })
     max_tokens = 16
     stream = $false
   } | ConvertTo-Json -Depth 4
   $reply = Invoke-RestMethod -Method Post -Uri 'http://127.0.0.1:11434/v1/chat/completions' -Headers @{ Authorization = 'Bearer ollama' } -ContentType 'application/json' -Body $body
   $reply.choices[0].message.content
   ```

2. Проверьте подключение StepFlow. Для Docker используйте порт 3000. Ответ `configured: True` означает, что Go получил все три переменные. Доступность модели проверяется запросом генерации или поиска.

   ```powershell
   Invoke-RestMethod 'http://localhost:3050/api/search'
   ```

### Примеры в интерфейсе

Если кнопки ИИ пропали, включите их в **Профиль → Настройки сайта → Функции ИИ**.

| Функция | Что попробовать | Что должно получиться |
| --- | --- | --- |
| Поиск по смыслу | В каталоге выберите категорию **Все**, введите «Как запустить проект в контейнерах?» и нажмите **Найти с ИИ**. | В выдаче есть «Запустить проект в Docker Compose». Под полем появляется сообщение «Инструкции подобраны ИИ по твоему запросу». |
| Черновик | Войдите как автор. В новом черновике введите «Как подготовить отчёт по лабораторной» и нажмите **Предложить варианты с ИИ**. Раскройте шаги одного варианта и нажмите **Использовать вариант**. | В редакторе появились текст, шаги и чек-листы. Поменяйте заголовок шага, сохраните черновик и откройте его снова. Правка сохранилась. |
| Подсказка по шагу | Откройте опубликованную инструкцию про Docker Compose, нажмите **Я застрял на этом шаге** и спросите «Как проверить, что Docker запущен?». | Напарник отвечает с учётом текущего шага. Откройте другой шаг и вернитесь к первому. Пока открыта инструкция, переписка первого шага сохраняется. |
| Общий чат | Откройте **Напарник** в меню и спросите «Как составить план учебной презентации?». | Приходит ответ по теме. Задайте уточнение «А если у меня только пять минут?», чтобы проверить продолжение разговора. |
| Скриншот в чате | Сохраните PNG с надписью `ERROR 2847: FILE MISSING`. Прикрепите его в Напарнике и спросите «Какой номер ошибки указан на скриншоте?». Повторите в подсказке по шагу. | Ответ содержит `2847`. Номер должен быть только на картинке. Поддерживаются PNG, JPEG и WebP до 2 МБ. |

Для проверки скриншотов скачайте `ollama pull qwen3-vl:2b-instruct` и выставьте `AI_MODEL=qwen3-vl:2b-instruct` перед перезапуском локального Go. В Compose этот тег используется по умолчанию.

До нажатия **Найти с ИИ** каталог ищет по словам и синонимам. После нажатия модель ранжирует опубликованные инструкции выбранной категории по названию, описанию и заголовкам шагов. Точный состав выдачи зависит от модели и содержимого каталога. Кнопка **Искать по словам** возвращает обычную выдачу.

Если `configured` равен `False`, проверьте настройки модели и перезапустите StepFlow. При `502` проверьте прямой запрос к Ollama и совпадение тега с `AI_MODEL`. Поиск ждёт до 15 секунд. Перед показом прогрейте модель коротким запросом. Ручной редактор и поиск по словам доступны при выключенной Ollama.

## Автоматическая модерация

Войдите как администратор и включите **Админ-панель → Очередь → Автоматическая модерация с ИИ**. Настройка по умолчанию выключена. Go обрабатывает текущую очередь и новые заявки на публичную публикацию в фоне. Можно закрыть вкладку администратора.

От имени автора создайте три отдельные инструкции и отправьте их на проверку. У каждой заполните описание, действия и хотя бы один пункт чек-листа, чтобы редактор принял заявку.

| Заявка | Пример содержания | Ожидаемый результат |
| --- | --- | --- |
| Понятная текстовая инструкция | «Как сложить лист пополам». Шаг 1 — положить лист на стол. Проверка — лист лежит ровно. Шаг 2 — совместить края и пригладить сгиб. Проверка — края совпали. | Статья появляется в каталоге. На вкладке **Решения** указаны «Опубликована» и **ИИ-модератор**. Автор получает уведомление. |
| Явная реклама без инструкции | «Распродажа». Описание — «Скидки только сегодня». Вместо действия — «Покупайте скорее». Пункт чек-листа — «Акция». | В **Решениях** появляется «На доработку» с причиной. У автора в **Мои инструкции** статья получает статус «Нужны правки». Автор получает уведомление. |
| Статья с вложением | Возьмите пример с листом, добавьте изображение к шагу и отправьте на проверку. | Статья остаётся в очереди. В карточке видна причина ручной проверки, доступны кнопки публикации и возврата. |

После автоматического возврата автор может открыть замечание, поправить статью и отправить её снова. При сбое модели Go повторяет проверку. После трёх неудачных попыток заявка остаётся у администратора с пояснением. Сервер проверяет только текстовые заявки без медиа, а спорные случаи передаёт человеку.

## Сценарий для показа

Для репетиции с чистой базой используй [сценарий с демо-аккаунтами и учебной инструкцией](docs/demo.md).

1. На лендинге откройте демо или зарегистрируйтесь как **Автор**. Создайте инструкцию с нуля либо выберите шаблон. При настроенном ИИ можно ввести тему и получить редактируемый черновик. Проверьте шаги и отправьте материал на модерацию.
2. В другом профиле браузера зарегистрируйтесь как **Администратор (демо)**. В разделе «Админ-панель → Очередь» можно опубликовать инструкцию или вернуть её с замечанием.
3. Подключите демо-подписку, затем назначьте аккаунт экспертом в разделе «Админ-панель → Эксперты». Откройте опубликованную инструкцию и оставьте рецензию. При подтверждении в каталоге появляется отметка «Проверено экспертом». После изменения материала экспертные отметки требуют новой проверки.
4. Зарегистрируйтесь как **Ученик**. Отметьте пункты шага, оставьте комментарий, вопрос или оценку. Вопрос увидит автор. Можно сделать форк с указанием исходника.
5. Вернитесь к автору и откройте «Статистика и вопросы» у своей инструкции. В таблице видны читатели, открывшие и завершившие шаг, незавершённые прохождения и вопросы. Последний незавершённый шаг обновляется по мере прохождения. Чтобы увидеть свежие данные, вернитесь в окно автора или обновите страницу.
6. В опубликованной инструкции нажмите «Скачать PDF» или «Сохранить офлайн». Офлайн-копии и их отметки доступны на устройстве. Приложение открывает офлайн-библиотеку, когда теряет сеть. Для Service Worker нужен localhost или HTTPS.
7. Кнопка «Встроить на сайт» выдаёт код iframe. Опубликованный материал открывается в нём без входа и проходится по шагам. Отметки iframe относятся к текущему просмотру.

### Дополнительные сценарии

| Функция | Действие и ожидаемый результат |
| --- | --- |
| Повторная подача и ручная модерация | Выключите автомодерацию. Автор отправляет «Подготовить отчёт по лабораторной». Администратор возвращает с замечанием «Укажи единицы измерения в первом шаге». Автор дополняет шаг и отправляет снова. После ручного одобрения статья появляется в каталоге, а оба решения видны в истории. |
| Прогресс, комментарии и вопросы | Ученик открывает опубликованный отчёт, оставляет комментарий и спрашивает, что делать, если измерения отличаются. Затем отмечает чек-лист и завершает шаг. После перезагрузки прогресс сохранён. В статистике автора виден завершённый шаг и вопрос. После ответа автора ученик получает уведомление. |
| Рейтинг и форк | Поставьте «Полезно» и в каталоге выберите **По полезности**. У карточки видна доля полезных голосов и их количество. Сделайте форк и поменяйте заголовок в черновике. У копии есть ссылка на исходник, исходная статья сохраняет свой заголовок. |
| Экспертная рецензия | На отдельном аккаунте включите обычную демо-подписку. Администратор назначает этот аккаунт экспертом по email. Эксперт оставляет положительную рецензию на чужую инструкцию. В каталоге появляется «Проверено экспертом». |
| Командная инструкция | На тарифе **Бизнес** создайте команду «Лаборатория» и добавьте ученика по email. Создайте инструкцию в команде и опубликуйте для команды. Участник может её открыть, а аккаунт вне команды не видит её в публичном каталоге и не может открыть по прямой ссылке. |
| PDF и офлайн | Откройте публичную инструкцию и скачайте PDF. Проверьте заголовок и чек-листы в файле. Нажмите **Сохранить офлайн**, дождитесь сохранения и откройте офлайн-библиотеку. Отключите сеть. Сохранённая инструкция открывается, а отметки остаются на устройстве. |
| Встраивание | Нажмите **Встроить на сайт**, вставьте скопированный iframe в HTML-страницу и откройте её в отдельном профиле. Опубликованная инструкция доступна без входа, чек-лист позволяет пройти шаги внутри iframe. |
| Работа при выключенном ИИ | Отключите функции ИИ в настройках сайта. В каталоге пропадает кнопка ИИ-поиска, поиск по словам продолжает находить инструкции. В редакторе можно создать и сохранить черновик вручную. |

Вход в режиме стенда работает по email без пароля. Сеанс и проверка ролей для действий выполняются на сервере. Роли на стенде выбираются при регистрации. Для публичной эксплуатации потребуется вход с подтверждением и отдельная выдача повышенных ролей.

В старом браузере на том же адресе можно открыть профиль под прежним email и нажать «Перенести старые инструкции». Копии попадут в черновики. Прогресс и оценки прежней локальной версии остаются в её хранилище.

## Структура проекта

- `frontend/src/app` и `frontend/src/components` — страницы и компоненты интерфейса.
- `frontend/public` — изображения, иконки и Service Worker.
- `frontend/src/lib` — экспорт PDF, офлайн-хранение и функции интерфейса.
- `backend` — Go API, SQLite, сессии, модерация, команды, уведомления и ИИ. Тесты запускаются командой `npm run backend:test`.
- `frontend/src/app/api` — маршруты, которые передают запросы в Go под тем же адресом сайта. Страница встраивания запрашивает только публичную инструкцию через Go.
- `backend-ts` — предыдущая реализация API и исходные данные примеров. Формат базы и cookie сессии совместимы с Go.
- `shared` — типы данных и поиск по словам.
